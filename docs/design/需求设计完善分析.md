## 一、真实业务输入 vs PRD 的差异

### 1.1 学科维度：PRD 设计了 6 科，实际是 7 科

| 学科 | PRD 覆盖程度 | 家长会要求 | 日程表实际内容 |
|------|-------------|-----------|---------------|
| 语文 | 简略（实虚词、红楼梦） | 详细：文言手册训练、150实词18虚词、必修默写、红楼梦21-40回、读书札记 | 4周分周计划(P1-20→P20-34→P34-49→P49-64) |
| 数学 | 简略（天利38套周2套） | 详细：8套模拟题/限时2h、基础弱3天1套、可拆分专题训练、选择填空40min限时 | 8套具体试卷名（海淀/西城/东城/朝阳期末卷等） |
| 英语 | 较详细（听口、词汇、完型） | 很详细：天学网平台操作、听说套题20套、应用文+阅读表达、写作拍照上传 | 听说×3/周、完形×3/周、词汇P75-83、口语专练分号 |
| 物理 | 简略（三选一方案） | 详细：3套分层方案、90分钟掐时练海淀套题、力学→电学→热光原复习节奏 | 万有引力→机械能动量→薄弱选做→历年期中卷 |
| 化学 | 孤立（价类二维图） | 详细：需购买鲁科版必修一二、元素化合物梳理框架(结构/性质/用途/制备)、实验重做、规范作答 | 轻松假期1-14+化工流程+专题三四+基础方程式 |
| 生物 | 孤立（教材精读） | 很详细：三轮复习节奏、核心概念与情境关联、精读教材四要点(逻辑/场景/表述/小栏目)、长句作答规范 | 西城单元+必修二/选必一二三教材+知识填空+例题 |
| **体育** | **几乎忽略** | **非常详细**：9-11月体质测试、5月合格考(单项<45不合格)、跑操计成绩 | 跑步10-20km/周、引体向上3-5次/周、核心力量3-5次/周、下肢3-4次/周 |

**结论**：PRD 对各科的描述停留在"举例"层面，而真实业务有精确到页码的作业清单和可操作的教学安排。体育学科的重视程度被严重低估——家长会用了一个完整章节（10分钟）专门讲体育。

### 1.2 时间节奏维度：PRD 缺少关键考核节点

家长会明确了以下关键时间节点，PRD 中完全没有体现：

| 时间 | 事件 | 影响 |
|------|------|------|
| 2026年8月（整月） | 学校装修、无返校 | 暑假是唯一自主支配黄金期 |
| 2026年9月 | 开学 + 双周学科统练启动 | 高频考试压力开始 |
| 2026年9-11月 | 国家体质健康测试 | 体育成绩入档 |
| 2026年10月 | 正式月考 | 首次赋分排名 |
| 2026年11月 | 海淀区期中统考 | 全区赋分排名 |
| 2026年12月 | 英语听口考试 | 取得优势可减负 |
| 2027年5月 | 体育学业水平合格考 | 单项<45分不合格 |

**结论**：PRD 只提到了"高考倒计时300天"和"听口倒计时130天"，遗漏了 **双周统练、月考、期中统考、体质测试、体育合格考** 五个关键节点。这导致系统无法提供完整的"学期考核里程碑规划视图"。

---

### 1.3 作息模型：PRD 的 12 小时设计与真实作息有偏差

**PRD 设计**：一个 "12 小时净学习时长" 的刻度线

**真实日程表**（xlsx）：
```
7:30    起床
8:30-9:00   晨读背诵（语文+英语）
9:00-10:30  第一节课（数学/物理）
10:45-12:15 第二节课（语文）
13:15-14:45 第三节课（物理/化学）
15:00-16:30 第四节课（生物/化学）
17:00-18:00 体育锻炼
19:00-20:30 第五节课（英语）
20:45-22:15 第六节课（整理复习/课外阅读）
23:30    睡觉
```

实际净学习时间 = 1.5h × 6 = 9h（不是 12h）。12h 是"在校节奏"的总要求，包含了晨读、课间等。

**结论**：计时器应该按 **6 个课时段** 而非简单的总时长来设计，每个时段绑定科目。当前的 `daily_executions` 表有 `duration_minutes` 字段但没有时段/节次概念。

### 1.4 打卡防自欺：真实要求比 PRD 更严格

| PRD 设计 | 家长会实际要求 |
|----------|---------------|
| "黑笔作答、红蓝笔订正"声明 | ✅ 一致 |
| 拍照上传 | ✅ 一致 |
| 未提及 | 语文：带答案的练习**必须用不同色笔及时订正**，避免错误留存 |
| 未提及 | 数学：限时2小时做套题，**不能超时** |
| 未提及 | 英语：写作**拍照上传**天学网，平台自动批改 |
| 未提及 | 生物：需**主动思考填空意义、亲自做例题后核对答案** |
| 未提及 | 化学：**定期巩固基础方程式书写**，做到又快又准 |

**结论**：防自欺不仅要"有无痕迹"，还需要**按学科定制验证规则**。数学套题要验证限时、英语写作要上传、生物要确认"亲自做例题"——当前系统只有通用的 `is_done` + `notes` 字段，无法做到学科级差异化验证。

## 三、需求设计需要补充和完善的内容

### 3.1 数据模型层 — 缺 4 张关键表

当前 7 张表无法支撑以下业务：

**需要新增的表：**

#### (1) 学科模板表 `subject_templates`
```sql
-- 存储家长会要求的各科标准任务模板，支持一键导入
CREATE TABLE subject_templates (
  id INTEGER PRIMARY KEY,
  subject TEXT NOT NULL,        -- 语文/数学/英语/物理/化学/生物/体育
  task_name TEXT NOT NULL,      -- 任务名称
  frequency TEXT,               -- 频次（每日/隔日/周3次）
  estimated_minutes INTEGER,    -- 预计耗时（分钟）
  week_number INTEGER,          -- 适用周次（1-4，NULL表示全周期）
  detail TEXT,                  -- 具体要求（如"限时2小时"、"黑笔作答红蓝笔订正"）
  verification_type TEXT        -- 验证类型（photo/timed/declaration/none）
);
```

#### (2) 考核节点表 `exam_milestones`
```sql
-- 存储学期关键考核节点
CREATE TABLE exam_milestones (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,           -- 节点名称（如"海淀期中统考"）
  exam_date TEXT NOT NULL,      -- 日期
  exam_type TEXT,               -- 类型（统练/月考/期中/听口/合格考）
  subject TEXT,                 -- 学科（NULL表示全科）
  weight TEXT                   -- 重要性（critical/high/normal）
);
```

#### (3) 错题表 `mistake_logs`
```sql
-- 存储错题反思卡片（Sprint 2 核心）
CREATE TABLE mistake_logs (
  id INTEGER PRIMARY KEY,
  node_id INTEGER,              -- 关联任务节点
  subject TEXT NOT NULL,
  question_text TEXT,           -- 题干
  wrong_answer TEXT,            -- 错误答案
  correct_answer TEXT,          -- 正确答案
  mistake_tag TEXT,             -- 错误归因（概念模糊/审题不清/计算失误/表述不规范）
  knowledge_point TEXT,         -- 关联知识点
  reflection TEXT,              -- 反思说明
  image_url TEXT,               -- 题目照片
  resolved BOOLEAN DEFAULT 0,   -- 是否已消化
  created_at TIMESTAMP
);
```

#### (4) 学习时段表 `study_sessions`
```sql
-- 记录分时段的学习计时（对应真实作息表6节课）
CREATE TABLE study_sessions (
  id INTEGER PRIMARY KEY,
  node_id INTEGER,              -- 关联任务
  session_date TEXT NOT NULL,
  period_number INTEGER,        -- 节次(1-6)
  subject TEXT,
  start_time TEXT,
  end_time TEXT,
  duration_minutes INTEGER,
  distraction_count INTEGER DEFAULT 0,  -- 分心次数
  created_at TIMESTAMP
);
```

### 3.2 功能模块层 — 需要补充的设计

#### A. 学科任务模板库（Sprint 1 核心缺失）

**业务背景**：家长会明确了 7 科的具体作业内容和频次。日程表 xlsx 精确到每周每科的任务。

**设计要点**：
- 7 个学科 × 4 周的矩阵式模板
- 用户选择"导入语文模板"→自动创建节点（TASK 类型）并关联到当前主题
- 支持导入后修改（调整任务内容、耗时、频次）
- `subject_templates` 表作为数据源，seed.js 初始化时预填充

#### B. 倒计时系统（Sprint 1 核心缺失）

**业务背景**：家长会确定了至少 6 个关键日期。

**设计要点**：
- 首页顶部固定双倒计时：高考倒计时 + 英语听口倒计时
- 支持切换到其他节点（期中统考/月考/体质测试）
- 数据源：`exam_milestones` 表
- 英语听口倒计时关联预警逻辑：当日英语任务未完成→红色闪烁

#### C. 学习计时器（Sprint 1 核心缺失）

**业务背景**：真实作息是 6 节课结构（xlsx），不是简单的总时长。

**设计要点**：
- 按 6 个时段（对应 xlsx 的作息表）
- 每节课绑定一个学科
- 支持"开始专注"/"暂停"/"结束"操作
- 记录分心次数
- 日终汇总 vs 12h 标尺
- 数据存入 `study_sessions` 表

#### D. 打卡防自欺系统（Sprint 1 核心缺失）

**业务背景**：不同学科有不同的验证要求。

**设计要点**：
- 通用验证（all subjects）：勾选"已用黑笔作答，红/蓝笔订正"
- 拍照验证（语文/英语作文/生物）：上传作业照片
- 限时验证（数学套题）：记录实际耗时 vs 限时 120min
- 平台验证（英语天学网）：标记"已在平台完成"
- 验证未通过 → 任务不能标记为 100% 完成
- `subject_templates.verification_type` 驱动验证逻辑

#### E. 执行阻碍标签系统

**业务背景**：PRD 定义了4个标签，但家长会提供了更多线索。

**设计要点**（预设标签，支持多选）：
- "题目偏难，大幅超出用时"
- "基础概念模糊，需再精读教材" ← 家长会反复强调
- "专注度下滑，受外界/手机干扰" ← 家长会强调手机管控
- "顺利掌握，完成质量高"
- "审题不清/读题遗漏" ← 化学老师强调
- "答题表述不规范" ← 化学/生物老师强调
- "计算失误" ← 数学老师强调

#### F. 每周任务看板

**业务背景**：日程表 xlsx 本身就是按"第一周/第二周/第三周/第四周"组织的。

**设计要点**：
- 以"周"为单位的任务聚合视图
- 显示"本周任务 vs 已完成"
- 与阶段（Phase）数据联动
- 支持按周切换查看

## 五、总结

**核心发现**：当前项目实现了"规划管理"的基础 CRUD 能力（主题/节点/阶段/执行记录），但 PRD 中 Sprint 1 定义的"学习引擎"核心特性——**倒计时、计时追踪、防自欺打卡、任务模板导入**——几乎全部缺失。真实业务参考资料（家长会 + 日程表）提供了比 PRD 更具体、更可操作的学科级需求，当前数据模型和功能设计需要补充至少 **4 张新表** 和 **6 个功能模块** 才能覆盖真实使用场景。
